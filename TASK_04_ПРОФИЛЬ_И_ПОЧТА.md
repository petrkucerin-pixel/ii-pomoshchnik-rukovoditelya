## Ожидаемое поведение

### Профиль (`pomoshnik/profile.py`)
- Профиль — папка `profiles/<id>/` с файлом `profile.md` в формате `leader_profile.md` заказчика. Это текст, а не код.
- `load_profile(dir)` читает `profile.md` и разбирает разделы: имя и должность, цели, «Никогда без подтверждения», «Можно без подтверждения», каналы, ритм (время плана дня и итога недели), стиль.
- Правила профиля превращаются в настройки `rules.json`: какие категории писем только с подтверждением, какие делегировать и кому, какие в сводку, какие игнорировать, какие можно авто. Делает это модель по тексту профиля, а код проверяет результат: категории только из словаря, люди только из оргструктуры. Без модели работает разбор по ключевым словам.
- Если правила профиля не говорят о категории, письмо идёт руководителю. Безопасно по умолчанию.
- Данные профилей разделены: у каждого своя база `runtime/<id>.sqlite`.

### Разбор почты (`pomoshnik/triage.py`)
- Шаг 1, модель: по письму определить категорию из словаря, краткую суть и уверенность.
- Шаг 2, код: действие по правилам профиля — `спросить_руководителя`, `делегировать` (кому), `авто`, `в_сводку`, `игнорировать`, с причиной.
- **Жёсткий запрет, независимо от модели:** письма от руководителя руководителя и письма категорий «деньги», «кадры», «обязательства клиентам», «руководство» (по профилю) — только `спросить_руководителя`. Если модель не уверена, письмо тоже идёт руководителю.
- Отправитель определяется по оргструктуре: роль берётся из `org_structure.csv`, а не из письма.

### Слой модели (`pomoshnik/llm.py`)
- Один интерфейс `complete_json(system, user) -> dict`. Поставщик: любой OpenAI-совместимый адрес (DeepSeek сейчас; GigaChat, YandexGPT или локальная модель — правкой `.env`). Заглушка для тестов.
- Каждый вызов пишется в журнал: модель, токены, стоимость, длительность.

### Проверка точности (`pomoshnik/eval_triage.py`)
- Прогон 80 писем `data/task/inbox.csv`, сверка с `expected_action`. Два режима: категория из эталона (проверка правил) и категория от модели (проверка всей цепочки).

## Проверочные случаи
1. Правила, категория из эталона: точность ≥ 95 %, **0** писем «деньги / кадры / обязательства клиентам / руководство» без подтверждения.
2. Второй профиль: копия `profile.md` с другими правилами (например, «отчёты — руководителю») меняет решения без правки кода.
3. Категория, о которой профиль молчит, уходит руководителю.
4. Письмо от руководителя руководителя уходит руководителю, даже если модель назвала его «статус».
5. Низкая уверенность модели — руководителю.
6. Модель вернула категорию вне словаря или человека вне оргструктуры — отбрасывается.
