## Ожидаемое поведение

`pomoshnik/protocol.py`:
- `build_protocol(llm, transcript, *, title, meeting_end, org, rules=[])` → `Protocol` в формате образцов заказчика: шапка, заметки по темам, решения, «Дальнейшие шаги» (задачи), «Предложения ИИ» (нерешённые вопросы и риски).
- У каждой задачи и решения есть цитата из расшифровки. Код сверяет цитату с текстом (`yadro.quotes`). Если цитата не найдена, задача помечается «не подтверждена расшифровкой».
- Исполнитель: если имя есть в оргструктуре, ставится id человека. Иначе исполнитель остаётся как в речи и помечается «уточнить исполнителя».
- Срок: код переводит слова («к пятнице», «до конца месяца») в дату от конца встречи (`yadro.deadlines`). Без срока ставится срок по умолчанию через 3 рабочих дня с пометкой «срок по умолчанию».
- `render_markdown(protocol)` — текст протокола для Telegram и письма.
- `questions_from_previous(protocol)` — вопросы аватара на следующей встрече: по каждой задаче прошлого протокола и по каждому нерешённому вопросу.
- `ProtocolStore` (SQLite): черновик → утверждён / правка / отклонён. Время от конца встречи до черновика и до утверждения. История правок.
- Правки: руководитель пишет правку текстом («исполнитель второй задачи — Ольга, срок пятница»). Модель применяет её к протоколу, правка сохраняется, и последние правки подаются в следующие протоколы как правила руководителя.

## Проверочные случаи
1. Нормальный протокол: задачи с цитатами, найденными в расшифровке, исполнители из оргструктуры, сроки датами.
2. Выдуманная цитата: задача помечена, но не удалена.
3. Исполнитель не из оргструктуры — пометка «уточнить исполнителя».
4. Срока нет — срок по умолчанию с пометкой.
5. Правка руководителя меняет протокол и попадает в правила следующего протокола.
6. Повторное утверждение того же протокола ничего не меняет.
7. Вопросы по прошлому протоколу содержат каждую задачу и каждый нерешённый вопрос.
