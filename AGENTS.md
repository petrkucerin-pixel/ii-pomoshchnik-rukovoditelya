# Codex — «ИИ-помощник руководителя»

Начинай с [СЕССИЯ.md](СЕССИЯ.md), затем [README](README.md), [райдер](РАЙДЕР.md) и [план подготовки](ПОДГОТОВКА.md). Сверяй объём работы с выбранным сценарием и официальным ТЗ, когда оно появится. При разработке записывай в TASK ожидаемое поведение, запуск и критерии проверки. Рабочие приёмы, тесты, порты и уроки собраны в [CLAUDE.md](CLAUDE.md).

- Пит принимает продуктовые решения. Codex ведёт код, проверки и документацию. В отчёте указывай, как открыть результат и что удалось проверить.
- Этот репозиторий должен запускаться из собственного клона. В рабочей папке хакатона рядом есть учебное ядро клининга и тренировочные задачи. Их можно изучать локально. Порядок переноса заготовок уточняется у организаторов.
- Для демо держи учебный набор данных с вымышленными именами. Ключи используй через локальный `.env`. Рабочую переписку, токены и выгрузки с персональными данными храни вне истории Git.
- Когда согласуем сценарий, фиксируй правила доступа и допустимые действия в проверяемых условиях. В журнале продукта сохраняй основания, решения человека и сведения о выполненных действиях.
- Журнал разработчика — [ЖУРНАЛ_РАЗРАБОТЧИКА.md](ЖУРНАЛ_РАЗРАБОТЧИКА.md). После каждого законченного шага дописывай запись сверху: дата, что сделано, как открыть, что проверено. Чат журналом не считается.
- Репозиторий один и тот же в двух копиях: эта папка на компьютере и открытый GitHub `origin` https://github.com/petrkucerin-pixel/ii-pomoshchnik-rukovoditelya. Сведения пиши в файлы этой папки. На GitHub уходит тот же набор коммитов, когда Пит просит пуш. Отдельную историю только на одной из копий не создавать. До просьбы Пита не коммитить и не пушить.
