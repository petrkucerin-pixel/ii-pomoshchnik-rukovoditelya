# TASK_11: Робот Телемоста — аватар сам заходит во встречу

**Исполнитель:** Claude. **Пункт ТЗ:** стр. 3, п. 3 («участвует во встрече как живой аватар — на одной платформе»).
**Решения Пита 26–27.11:** аватар сам заходит в Телемост и уже подключён, без OBS и нажатий; робот на сервере, частью прода; в протокол должна попадать вся информация.

## Как устроено
- `pomoshnik/robot/__init__.py` — браузер Google Chrome без экрана (Playwright, канал `chrome`: в нём есть H.264, в котором LiveAvatar отдаёт видео). Заходит по ссылке гостем «ИИ-помощник Ивана Петрова» во фрейм комнаты `private-join`, нажимает «Подключиться».
- `pomoshnik/robot/bridge.js` — встраивается в страницу Телемоста. Телемосту вместо камеры — холст с видео аватара (до старта — заставка), вместо микрофона — голос аватара. Аватару вместо микрофона — смесь звука остальных участников (свой голос он не слышит). `bypass_csp`: политика страницы Телемоста иначе не пускает запросы к LiveAvatar и LiveKit.
- SDK аватара — `@heygen/liveavatar-web-sdk` 0.0.20 и `events` 3.3.0 (MIT, лежат в `pomoshnik/robot/vendor/` с лицензиями). Сессия FULL создаётся на стенде (`/v1/sessions/token`), контекст — тот же, что у аватара в окне: история, вопросы ревизора, прошлый протокол, задачи и участники встречи.
- `pomoshnik/robot/manager.py` — один робот за раз, поток на стенде. Робот выходит, когда: комнату закрыли, все ушли (2 мин), никто не пришёл (15 мин), вышло время, нажали «стоп».
- **Протокол** — из полной расшифровки LiveAvatar (ждём до ~45 с, пока сессия закроется), обрывки реплик склеены; если её нет — из расшифровки моста. В начало — участники встречи из Телемоста. Черновик уходит на утверждение в Telegram, как после обычной встречи.
- Ссылка Телемоста у встречи — в журнале (`meeting_link`). Автопилот: если у встречи есть ссылка, в начале встречи идёт робот; иначе — окно для студии (TASK_09).

## Говорящие
LiveAvatar получает общий звук встречи — кто говорит, он не знает. Поэтому: аватар просит представляться, не приписывает ответ тому, кому задал вопрос, переспрашивает «кто ответил». Протокол берёт исполнителя из обращения или из того, как человек назвал себя; задачи «вынести руководителю» — на руководителя.

## API
`PUT /api/meetings/{uid}/link {link}` · `POST /api/robot/start {link, title, uid?, minutes}` · `GET /api/robot` · `POST /api/robot/stop`. В карточке встречи — поле «Ссылка на комнату», кнопки «Аватар в Телемост сейчас» и «Сохранить ссылку», состояние робота.

## Проверено
- Живой тест с Питом 27.11: аватар во встрече (видео 1280×720, голос), 22 реплики в расшифровке LiveAvatar. Протокол на этой расшифровке: все договорённости и нерешённое попали.
- Найдено и исправлено: «12-го декабря» не разбиралось как срок (распознавание речи пишет с окончанием); эхо — аватар слышал себя; падение, когда комнату закрыли; имя «Гость».
- Нагрузка: ~60–85 % двух ядер во время встречи, память до 1,6 ГБ из 4.
- Тесты: `tests/test_robot_manager.py` (7), робот через API в `tests/test_server.py`, склейка и правило говорящих в `tests/test_avatar.py`, даты в `tests/yadro/test_deadlines.py`.

## Вне объёма
