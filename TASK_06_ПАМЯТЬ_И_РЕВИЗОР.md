# TASK_06: Память помощника и ревизор отчётов

**Исполнитель:** Claude. **Пункты ТЗ:** «агент забирает рутину», «доля писем без участия руководителя», профиль и правки. Решение Пита 26.11: руководитель сам ничего не загружает и не держит в голове. Помощник копит знания из потока и сам разбирает отчётность — проверяет и находит ошибки.

## Ожидаемое поведение

### Память (`pomoshnik/memory.py`)
- Каждое письмо, отчёт и протокол → факты: `тема` (сделка, партнёр, метрика, задача), `что` (статус, цифра, срок), `кто`, `когда`, `источник` (id письма или протокола), цитата.
- Факты извлекает модель, а код проверяет цитату по исходному тексту (`yadro.quotes`). Факт без подтверждённой цитаты не сохраняется.
- Поиск: по теме и по словам (SQLite FTS5). История одной темы по времени.
- Данные профилей разделены: своя база у каждого руководителя.

### Ревизор отчётов (`pomoshnik/reports.py`)
Письма категорий «отчёт» и «статус» проходят проверки **в коде**:
1. **Нет движения:** тот же статус от того же человека повторяется N дней (по умолчанию 3) → вопрос исполнителю «что мешает».
2. **Расхождение со сроком задачи:** в задачах срок прошёл или другой, чем в отчёте → вопрос исполнителю: обновить срок или объяснить.
3. **Сверка цифр:** одна метрика из двух источников (прогноз 94 % и отклонение −6 %) — сходится или нет. Не сходится → вопрос обоим.
4. **Нет деталей:** «риск по двум сделкам» без названий → уточнение у автора.
5. **Пропущенный отчёт:** задача «отчёт …» просрочена, а писем нет → напоминание исполнителю.
6. **Риск для цели руководителя** (цель из профиля, например «выполнить план продаж») → одна строка руководителю в план дня.

Вопросы исполнителям идут путём «сам, сразу»: это внутренние письма. Руководитель видит одну строку сводки на отчёт и отдельную строку риска. Один и тот же вопрос по одной теме не задаётся повторно в течение суток.

## Проверочные случаи (на данных заказчика)
1. «Облако Плюс» 7 раз за 5 дней → один вопрос Сергею, а не семь.
2. Задача t005 со сроком 01.12 против «ждём до 12.12» → расхождение найдено.
3. 94 % и −6 % → «сходится», вопроса нет. Если подменить на 94 % и −9 % → расхождение и вопрос.
4. «Риск по двум сделкам» → уточнение у Ольги.
5. t007 «Отчёт по e-com за ноябрь» просрочен, писем нет → напоминание Анне.
6. Прогноз ниже 100 % при цели «выполнить план» → строка риска руководителю.
7. Факт с цитатой, которой нет в письме, не сохраняется.

## Итог, 26 ноября 2026

**Ревизор** — готов (коммит `2ab47cb`). Случаи 1–6 проходят. На 18 отчётах заказчика найдено 8 пунктов, руководителю уходит одна строка о риске плана продаж.

**Память** — готова, не задеплоена.
- `pomoshnik/memory.py`: модель извлекает факты, код сверяет цитату (не короче 3 слов). Факты хранятся в SQLite, поиск через FTS5 по началу слова: «облака» находит «Облако». История темы идёт по времени, повтор одного факта из того же источника не сохраняется.
- Своя база у профиля: `runtime/<профиль>_memory.sqlite`.
- В помощнике: в память идут письма всех категорий, кроме рассылок, приглашений, доступов и календаря, а также утверждённые протоколы (черновики не идут). В Telegram работают «что по …», «что с …», «что известно о …» и `/chto`. Одинаковый статус подряд показывается одной строкой: «08.12–11.12, 7 раз без изменений».
- Случай 7 проходит. Проверка на прочность: выключил сверку цитаты, фильтр рассылок и запись протокола — каждый раз тест падал.
- Живой замер, DeepSeek Flash, 18 отчётов и статусов: модель дала 24 факта, все 24 прошли сверку цитаты, 36 с, $0,0089. На все 80 писем выйдет примерно 60 вызовов, около $0,03 за прогон почты.
